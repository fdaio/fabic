# fabic · エージェント協働ハンドブック

特定のプロジェクトに依存しないエージェント協働ハンドブックです。Amy、Eva、Bob、Con の 4 つの役割について、職務、引き継ぎ条件、レビュー工程、マージルールを定義します。

このリポジトリはハンドブックとテンプレートのみを保存します。ランタイム、データベース、ボード、プロジェクト固有のデータは含みません。

## 使い方

1. まず `AGENTS.ja.md` を読んでください。チームのすべての制約の唯一の情報源です。
2. 自分の役割に対応する `docs/agent/` 配下のマニュアルを読んでください。
3. プロジェクトを接続するとき、プロジェクト側は独自のリポジトリ、issue トラッカー、CI、チェックコマンドを使い続けます。このハンドブックは協働ルールのみを提供します。
4. 例ではプレースホルダーのみを使います: `<project>`、`<repo>`、`<default-branch>`、`REQ-001`、`example.com`。

## ワークフロー

```text
新しいプロジェクトの接続
  -> Eva の環境受け入れ
  -> Amy の要件確認と承認
  -> Bob の実装 + 自己テスト（feature ブランチ）
  -> Con の受け入れテスト
  -> Con が PR を作成
  -> 階層レビュー + CI
  -> デフォルトブランチへマージ
  -> worktree の削除
```

- 環境が使えない: Eva またはメンテナーに戻す。Bob は実装を開始しない。
- テスト失敗: Con が記録し、Bob に差し戻す。
- 3 回連続のテスト失敗: Con はテストを停止して Amy に報告する。新しい受け入れラウンドを開始できるのは Amy だけです。
- リスクの等級が上がった: Bob または Con は停止し、Amy に戻して再分類する。マージ直前にユーザーへ確認しない。

## 保守原則

- ハンドブックを特定のプロジェクトから切り離す: リポジトリ名、組織名、顧客名、内部プロジェクト名、ローカルパスを書かない。
- 個人情報、顧客情報、内部プロジェクト情報、認証情報、実在の業務データを記録しない。
- ルールの変更はまず `AGENTS.md` に行う。役割の操作詳細は `docs/agent/` に置く。
- 翻訳は中国語版を正本とする。ルールの変更はまず中国語版を直し、その後 `.en.md` と `.ja.md` を同期する。
- ドキュメントが主張する動作は、ルールまたは現場で実行したプロジェクトのコマンドに基づかなければならない。
