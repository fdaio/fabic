# Eva 環境受け入れマニュアル

Eva はプロジェクト環境の準備と検証を担当します。Eva はこのハンドブックが定義するプロセス役割であり、現在のセッションがこのマニュアルに従って実行します。独立したエージェントでも subagent でもなく、`@Eva` や Task では呼び出しません。

---

## 目標

実装開始前に、このマシンでプロジェクトをビルドでき、テストできることを証明します。環境を準備できない場合は、プロジェクトを `Unmaintainable` とし、メンテナーに通知し、実装に入りません。

---

## 適用範囲

プロジェクトのドキュメント、`Makefile`、タスクスクリプト、CI 設定が宣言するツールチェーンとチェックコマンドを使います。一般的な既定コマンド:

| エコシステム | 依存関係 | ビルド | テスト |
|------|------|------|------|
| Go | `go mod download` | `go build ./...` | `go test ./...` |
| Node | `npm ci` | `npm run build` | `npm test` |
| Python | `pip install -r requirements.txt` | プロジェクトが宣言するビルドコマンド | `pytest` |
| Rust | `cargo fetch` | `cargo build` | `cargo test` |

プロジェクトがコマンドを宣言していない場合はエコシステムの既定コマンドを実行します。それでも判断できない場合は `Unmaintainable` とし、理由 `unsupported project type` を記録します。

明示的に対象外:

- コンテナ、リモート CI、外部サービスがないとビルドまたはテストできないプロジェクト。
- システムツールチェーンの自動インストールやアップグレードがないと通らないプロジェクト。
- ビルドまたはテストの失敗を自動修復しないと通らないプロジェクト。
- 再現可能なチェックコマンドがないプロジェクト。

---

## トリガー

- 新しいプロジェクトの接続時。
- 環境変更後の再チェック。
- 失敗後の再試行。
- 同じプロジェクトで同時に実行するチェックは 1 つだけ。

---

## 実行

プロジェクトルートで非対話的に実行し、1 回のチェックの合計タイムアウトは 15 分です。

1. プロジェクトパスが存在し、宣言されたツールチェーンが利用可能か確認する。
2. プロジェクトのドキュメントに従って依存関係をインストールする（プロジェクトのキャッシュまたは依存ディレクトリのみ）。
3. ビルドコマンドを実行する。
4. テストコマンドを実行する。

実行上の制約:

- プロジェクトファイルを変更しない。
- `go mod tidy`、`go generate`、整形、コード生成など、プロジェクトを書き換えるコマンドを実行しない。
- 依存関係はプロジェクトのキャッシュのみに入れる。ビルドとテストはキャッシュディレクトリのみを使う。
- データベース、コンテナ、外部サービスを起動しない。
- 認証情報、token、完全な環境変数を記録または出力しない。

---

## Con が受け入れに使うテスト環境

`Environment Ready` は、Con が受け入れテストに使う環境も定義します。Con はタスク worktree 内で、同じプロジェクトパス、ツールチェーン、依存キャッシュを使い、次を実行します。

1. プロジェクトのドキュメントが宣言する依存インストールコマンド。
2. プロジェクトのドキュメントが宣言するビルドコマンド。
3. プロジェクトのドキュメントが宣言するテストコマンド。
4. プロジェクト既存の lint とテストコマンド。lint にベースラインの問題がある場合、Con はベースラインの問題を別途記録する。今回の変更で新しい問題を追加してはいけない。

Eva は独立したコンテナ、仮想マシン、外部サービスを作成しません。受け入れ中に環境が壊れた場合、プロジェクトが受け入れ条件を満たさなくなった場合、またはツールチェーンが使えなくなった場合、Con はテストを停止し、Eva/メンテナーに戻して再チェックします。Con 自身は修復しません。

環境の問題は Bob のテスト失敗ではなく、Con の 3 回失敗の回数に含めません。

---

## 判定

### Environment Ready

次をすべて満たす:

- パスが存在し、宣言されたツールチェーンが利用可能。
- 依存インストール、ビルド、テストがすべて終了コード 0。
- プロジェクト内に少なくとも 1 つの自動テストファイルがある。
- テストがマシンの既定環境で自己完結して通り、外部サービス、データベース、認証情報、特別な環境変数に依存しない。

### Unmaintainable

次のいずれかに該当する:

- プロジェクトパスが存在しない。
- 再現可能なビルドまたはテストコマンドがない。
- 宣言されたツールチェーンが利用できない。
- 依存インストール、ビルド、テストが失敗する。
- 自動テストファイルが 1 つもない。
- テストに外部サービス、データベース、認証情報、特別な環境変数が必要。
- チェックが 15 分を超える。
- プロジェクト種別が対象外。

失敗記録には次を含める: プロジェクト名、状態、失敗したステップ、終了コード、主要な出力。主要な出力は問題の特定に必要な行だけを残し、認証情報や完全な環境変数を含めない。

---

## 通知

- **タスク記録:** プロジェクト名、状態、失敗したステップ、理由を記録する。
- **メンテナー:** 現在のセッションを実行しているユーザー、つまりプロジェクトの所有者。
- **GitHub Issue、webhook、その他の外部チャネルで自動通知しない。**
- 結果はプロジェクトのタスク記録に書き、このハンドブックリポジトリには書かない。

---

## 引き継ぎ

- `Environment Ready`: Amy に戻す。Amy は要件の明確化を続け、確認後に Bob へ渡す。
- `Unmaintainable`: メンテナーに通知し、Amy に戻す。Amy は要件の明確化を続けられるが、Bob は実装を開始してはいけない。メンテナーが環境を修復した後に再試行する。

Eva は失敗結果を直接 Bob に渡さず、Bob に環境を自分で修復させません。

---

## 権限の境界

Eva は環境のチェックのみを行います。Eva は次を行いません。

- プロジェクトファイルや依存宣言の変更。
- システムツールチェーンのインストールやアップグレード。
- データベース、コンテナ、外部サービスの起動。
- ビルドやテストの失敗の自動修復。
- 業務コードの作成、コードレビュー、PR のマージ。
- Amy の要件明確化の代替。

---

## 状態

| 状態 | 意味 | Bob は開始できるか |
|------|------|----------------|
| `Unchecked` | 接続済みで未チェック | いいえ |
| `Environment Ready` | ビルドとテストが通る | はい |
| `Unmaintainable` | チェックに失敗 | いいえ |

既存プロジェクトは接続後 `Unchecked` となり、通過するまで実装を開始してはいけません。

---

## 実装状態

このマニュアルはルールのみを定義し、特定の CLI、データベース、ボードに依存しません。現在のセッションがこのマニュアルに従ってチェックを実行し、プロジェクトのタスク記録に結果を書きます。省略してはいけず、`Environment Ready` を口頭で宣言してはいけません。
